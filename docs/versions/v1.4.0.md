# v1.4.0

## Summary

Additive release. A `MongoQueries` can now be built on top of a client the
caller already owns, and derived for another database on the same client.
Until now `Connect` was the only constructor, and every call opened a new
`*mongo.Client` with its own connection pool.

No signature changed. Upgrading is a `go get`.

## Changes

### `NewFromClient` — build a handle on an existing client

```go
func NewFromClient(client *mongo.Client, dbName string, opts *ClientOptions) *MongoQueries
```

No ping and no log line: the client was already verified by whoever opened it.
A nil `opts` means `Debug` off, as in `Connect`. `Connect` itself now ends by
calling this, so there is one way to build the struct.

### `WithDatabase` — another database, the SAME client

```go
func (mongodb *MongoQueries) WithDatabase(dbName string) *MongoQueries
```

Returns a new handle that shares the receiver's connection pool and inherits
its `Debug` flag. The receiver is not modified.

This is the multi-tenant shape — one server, one database per tenant — without
one pool per tenant:

```go
registry, err := mongocc.Connect(uri, "registry", nil)   // the ONE client
tenantA := registry.WithDatabase("platform:tenant-a")     // no network I/O
tenantB := registry.WithDatabase("platform:tenant-b")
```

The motivating case was a factory that called `Connect` per tenant, cached the
result for five minutes, and called `Connect` again on expiry without
disconnecting the previous client — a pool per tenant, plus another one per
tenant every five minutes, with nothing failing while the sockets grew.

### `Database` — accessor to the underlying handle

```go
func (mongodb *MongoQueries) Database() *mongo.Database
```

`Name()` tells which database the handle operates on; `Client()` is the way to
`Disconnect` at shutdown — by the owner of the client, once. A handle built by
`WithDatabase` must not disconnect: the client is shared.

## Tests

`mongocc_handles_test.go` covers the three additions without a live MongoDB.
`mongo.Connect` in driver v2 does not dial — it starts the topology monitor in
the background and returns — so a URI at a closed port yields a client whose
`Database()` handles can be inspected. The key assertion is pointer equality on
the client across every handle derived from one base.

## Known Issues

- No CI workflow runs the tests. The repository only has `publish.yml`, which
  triggers on release.
- `MongoFunctions` interface does not include the new methods, nor
  `FindOneAndUpdate`, `InsertMany`, or `GetCollection`.
- Standalone `CheckMongoError` function is deprecated but still exported.
