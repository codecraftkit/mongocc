# v1.3.1

## Summary

Security fix. `Connect` no longer writes MongoDB credentials to stdout. This
release also adds the package's first tests.

**Upgrade is recommended for every service using mongocc.** Until this version,
each `Connect` call printed its full connection string — username and password
included — on every successful connection.

## Security

### Credentials are no longer printed on connect

`Connect` logged the raw connection string:

```go
fmt.Printf("You successfully connected to Mongo: %s db: %s\n", mongoUri, dbName)
```

The line was unconditional. `opts.Debug` is only read twelve lines later, so
passing `Debug: false` did not suppress it — there was no way to turn it off
from the caller. Anything capturing stdout (container logs, a log aggregator,
CI output) retained the credentials, and a service holding three databases wrote
three distinct passwords on every boot.

This was a partial regression from v1.3.0, which made debug logging configurable
through `ClientOptions.Debug` but left this line out of the change.

The URI is now rebuilt from its scheme and host before printing:

| Connection string | Logged as |
|:--|:--|
| `mongodb://appuser:s3cr3t@cluster.example.com:27017/billing?retryWrites=true` | `mongodb://cluster.example.com:27017` |
| `mongodb+srv://appuser:s3cr3t@cluster.abc.mongodb.net/billing` | `mongodb+srv://cluster.abc.mongodb.net` |
| `mongodb://a.example:27017,b.example:27017/billing?replicaSet=rs0` | `mongodb://a.example:27017,b.example:27017` |
| anything that does not parse into a scheme and a host | `[redacted]` |

Rebuilding is deliberate, and stronger than clearing the userinfo. Userinfo is
not the only part of a MongoDB connection string that can hold a secret: the
option string also carries `tlsCertificateKeyFilePassword` and the AWS session
token inside `authMechanismProperties`. Both are covered by tests, and both
survive the "set `User` to nil" approach. Keeping only what is known to be safe
means an option added to the connection string later cannot leak by omission.

**What you lose:** the URI path, normally the authentication database. The
message keeps its diagnostic value — `dbName` is still printed separately, so
"which server did this service attach to, and against which database" is still
answered.

**Rotate any credential that reached a log you do not control.** Upgrading stops
the leak; it does not retract what was already written.

## Fixes

### `CheckMongoError` no longer treats an error message as a format string

Both `CheckMongoError` functions ended with `return fmt.Errorf(err.Error())`. A
driver message containing a `%` was interpreted as a format verb and came out
mangled (`%!s(MISSING)`). Replaced with `errors.New(err.Error())`, which keeps
the message and the previous identity semantics.

This also unblocked testing the package at all: `go test` runs a subset of
`go vet` by default, and the `printf` check failed the build with "non-constant
format string in call to fmt.Errorf".

## Tests

`mongocc_test.go` is the package's first test file, covering the redaction with
18 cases across three tests: the exact output per URI shape, the security
assertion that no sentinel secret reaches the log line, and a guard that
redacting the whole line is not an acceptable way to pass that assertion.

All three were verified by mutating the production code, not only by watching
them pass.

## Known Issues

- No CI workflow runs the tests. The repository only has `publish.yml`, which
  triggers on release.
- `MongoFunctions` interface does not include `FindOneAndUpdate`, `InsertMany`,
  or `GetCollection`.
- Standalone `CheckMongoError` function is deprecated but still exported.
